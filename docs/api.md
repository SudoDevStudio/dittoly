# API

Everything the portal does is under `/api`, with the session cookie (plus the `X-Dittoly-Request: 1` header on writes) or `Authorization: Bearer <api token>`:

`POST /hooks/:id` answers `202 {"runId": "..."}` in the local install. On a shared server it answers `202 {"accepted": true}`, because the run is started by a worker after the reply. A repeated delivery ID gets `200 {"duplicate": true}`.

`POST /api/triggers` takes `provider`: `standard`, `github`, `gitlab`, or `token` for senders that cannot sign (Datadog monitor webhooks, Grafana contact points, Vector, Fluent Bit). A `token` trigger's secret (`dtywt_…`) is sent in `X-Dittoly-Token` or as `Authorization: Bearer`; an identical body is one delivery, and the optional `deliveryIdPointer`, `timestampPointer` and `maxAgeSeconds` (JSON Pointers into the payload) make the payload's own id and time limit replays.

`GET /api/triggers` returns only the current member’s trigger metadata, including its Flow, pinned version, provider, URL, and rate limit. Signing secrets are returned only at creation or rotation.
